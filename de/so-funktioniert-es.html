So funktioniert es

Was mit einer Datei geschieht, vom Hochladen bis zu dem Moment, in dem jemand sie öffnet, in einfachen Worten.

  • Ihr Gerät verschlüsselt Inhalt und Namen einer Datei, bevor irgendetwas gesendet wird.
  • Das Drive-Gateway ist der Server des Dienstbetreibers. Es verwaltet Konten, führt die verschlüsselte Liste Ihrer Dateien und gibt verschlüsselte Daten an das Netzwerk weiter. Es hat keine Schlüssel.
  • Speicheranbieter im Netzwerk The Only Grid (TOG) bewahren die verschlüsselten Daten redundant auf, im Rahmen von Speicherverträgen, die der Betreiber bezahlt.

1. Verschlüsselung auf Ihrem Gerät

Wenn Sie ein Konto erstellen, erzeugt die App auf Ihrem Gerät einen Hauptschlüssel für das Konto. Jeder Ordner, jede Datei und jede Dateiversion erhält einen eigenen Schlüssel, der daraus abgeleitet oder damit verpackt wird. Dateien werden in Blöcke aufgeteilt, die jeweils verschlüsselt und an ihre Datei und Position gebunden sind, sodass Blöcke nicht unbemerkt vertauscht, umsortiert oder abgeschnitten werden können. Namen werden mit dem Schlüssel ihres Ordners verschlüsselt. Dateien werden komprimiert, wenn es etwas bringt, und auf eine gerundete Größe aufgefüllt. Jede Version wird von dem Gerät signiert, das sie erstellt hat, daher würde eine auf dem Server gefälschte Datei abgelehnt. Der Hauptschlüssel gelangt nur verschlossen zum Server: mit Ihrem Passwort, Ihrer Wiederherstellungsphrase und jedem Geräteschlüssel. Die Anmeldung nutzt OPAQUE, daher erhält der Server Ihr Passwort nie. Wir verwenden gut geprüfte, öffentliche Algorithmen (unter anderem XChaCha20-Poly1305, Ed25519, X25519 mit ML-KEM-768, Argon2id) und keine selbst gebaute Kryptografie.

2. Was das Gateway sieht und was nicht

Das Gateway ist immer online, nimmt Uploads an, packt kleine Dateien in große Einheiten, hält einen kurzlebigen Zwischenspeicher verschlüsselter Daten für schnelleres Lesen und verwaltet die Speicherverträge. Geheimhaltung und Unversehrtheit müssen Sie ihm nicht anvertrauen. Es kann aber ausfallen oder Daten verlieren, deshalb sind die Kopien im Netzwerk wichtig.

3. Wie eine Datei im TOG-Netzwerk gespeichert wird

  1. Packen. Das Gateway sammelt verschlüsselte Blöcke vieler Personen zu großen Segmenten. Ein Segment enthält keine Kontonamen.
  2. Speichervertrag. Der Betreiber schließt für eine Gruppe von Segmenten einen Vertrag im TOG-Netzwerk ab und bezahlt ihn. Verträge laufen befristet (zum Beispiel 30 Tage), und das Gateway verlängert sie vor ihrem Ende.
  3. Redundanz (Erasure Coding). Jedes Segment wird zu einer größeren Zahl von Teilen, von denen nur einige zum Wiederaufbau nötig sind, zum Beispiel beliebige 10 von 14. Die Teile gehen an verschiedene Speicheranbieter.
  4. Prüfungen. Das Netzwerk prüft regelmäßig, ob die Anbieter wirklich aufbewahren, wofür sie bezahlt werden.
  5. Lesen. Das Gateway liefert aus seinem Zwischenspeicher oder baut die Daten aus den Teilen der Anbieter wieder auf, prüft, dass sie genau dem Gespeicherten entsprechen, und sendet Ihnen die verschlüsselten Blöcke. Ihre App entschlüsselt sie.

4. Verlängerung und Löschung

Das Gateway verlängert Verträge vor ihrem Ende. Enthält ein Segment überwiegend gelöschte Daten, packt das Gateway die noch genutzten Daten in ein neues Segment und lässt den alten Vertrag auslaufen. Wenn Sie eine Datei endgültig löschen, entfernt das Gateway sofort ihre Schlüssel und Einträge; verschlüsselte Daten, die Anbieter noch bis zum Ende des alten Vertrags halten (höchstens etwa 30 Tage), lassen sich nicht mehr entschlüsseln. Das nennt man Crypto-Shredding.

5. Schlüssel teilen

Jedes Konto hat einen öffentlichen Schlüssel. Beim Teilen eines Ordners wird dessen Schlüssel mit dem öffentlichen Schlüssel des Empfängers verschlossen und die Freigabe signiert; der Server transportiert nur das versiegelte Paket. Öffentliche Schlüssel verteilt vorerst das Gateway, daher zeigt die App einen Fingerabdruck zum Vergleich mit der Person, merkt ihn sich und warnt, wenn er sich ändert. Geplant ist, öffentliche Schlüssel im TOG-Netzwerk selbst zu veröffentlichen, damit nicht einmal das Gateway sie austauschen kann. Beenden Sie eine Freigabe, entzieht der Server den Zugriff sofort; was die Person bereits gelesen hat, bleibt bei ihr.

6. Öffentliche Links

Ein Link sieht so aus: https://server/l/id#schlüssel. Browser und Apps senden den Teil nach # nie an den Server. Der Server weiß also, dass der Link existiert, wie oft er geöffnet wurde und wann er abläuft, kann ihn aber nicht öffnen. Mit Passwort entsteht der Schlüssel aus Link und Passwort zusammen. Wer den Link hat, hat den Schlüssel; daher kann der Betreiber einen öffentlichen Link öffnen, der wegen Missbrauchs gemeldet wird. Private Dateien ohne Link kann niemand außer Ihnen und den Personen, mit denen Sie teilen, öffnen.

7. Wenn etwas verschwindet

  • Ein Speicheranbieter fällt weg: Dateien werden aus den übrigen Teilen wieder aufgebaut, und Verlängerungen wählen Anbieter, die funktionieren.
  • Das Gateway ist nicht erreichbar: Bis es wieder läuft, lässt sich nichts hoch- oder herunterladen; Dateien in Ihrem synchronisierten Ordner bleiben auf Ihrem Computer.
  • Sie verlieren ein Gerät: Widerrufen Sie es von einem anderen Gerät aus.
  • Sie verlieren Passwort und Phrase: Ohne angemeldetes Gerät lassen sich die Dateien nicht wiederherstellen. Das ist der Preis dafür, dass niemand sonst Ihre Schlüssel hat.

8. Alpha-Status

TOG Drive ist eine Alpha im Testnetz von The Only Grid, das von Grund auf neu gestartet werden kann, wobei Daten gelöscht werden. Das Verschlüsselungsformat ist noch nicht festgeschrieben, und vor einem öffentlichen Start mit echten Daten ist eine unabhängige Prüfung der Kryptografie im Client geplant. Die Redundanz im kleinen Testnetz ist geringer als später im Hauptnetz. Einige hier beschriebene Funktionen (öffentliche Schlüssel im Netzwerk, Öffnen von Links im Browser, mobile Apps) sind noch nicht fertig. Nutzen Sie TOG Drive zum Ausprobieren und bewahren Sie Kopien wichtiger Dateien woanders auf.
