How it works

What happens to a file from the moment you upload it to the moment someone opens it, in plain words.

  • Your device encrypts a file's contents and name before anything is sent.
  • The Drive gateway is the service operator's server. It runs accounts, keeps the encrypted list of your files and passes encrypted data on to the network. It has no keys.
  • Storage providers on The Only Grid (TOG) keep the encrypted data, with redundancy, under storage deals the operator pays for.

1. Encryption on your device

When you create an account, the app makes an account master key on your device. Every folder, file and file version gets its own key derived from or wrapped under it. Files are split into blocks, each encrypted and bound to its file and position, so blocks cannot be swapped, reordered or cut off unnoticed. Names are encrypted with their folder's key. Files are compressed when it helps and padded to a rounded size. Each version is signed by the device that made it, so a file forged on the server would be rejected. The master key goes to the server only locked by your password, your recovery phrase and each device key; sign-in uses OPAQUE, so the server never gets your password. We use well-reviewed public algorithms (among them XChaCha20-Poly1305, Ed25519, X25519 with ML-KEM-768, Argon2id), not home-made cryptography.

2. What the gateway sees and does not see

your username; encrypted blocks and their rounded sizes; how many files and folders you have and how they nest (no names); upload and change times; who you share with and with which rights; your public keys and device list; your IP address file contents; file and folder names; exact sizes and file types; your password and recovery phrase; decryption keys; public link keys (the part after #)

The gateway is always online, takes uploads, packs small files into large units, keeps a short-lived cache of encrypted data for faster reads and manages storage deals. You do not have to trust it with secrecy or integrity. What it can do is be unavailable or lose data, which is why the copies on the network matter.

3. How a file is stored on TOG

  1. Packing. The gateway gathers encrypted blocks from many people into large segments. A segment carries no account names.
  2. Storage deal. The operator opens and pays for a deal on the TOG network for a group of segments. Deals run for a limited term (for example 30 days) and the gateway renews them before they end.
  3. Redundancy (erasure coding). Each segment becomes a larger number of pieces, of which only some are needed to rebuild it, for example any 10 of 14. The pieces go to different storage providers.
  4. Checks. The network regularly checks that providers really keep what they are paid for.
  5. Reading. The gateway serves from its cache or rebuilds from providers, verifies the data is exactly what was stored, and sends you the encrypted blocks. Your app decrypts them.

4. Renewal and deletion

The gateway renews deals before they end. When a segment holds mostly deleted data, the gateway repacks the live data into a new segment and lets the old deal expire. When you purge a file, the gateway deletes its keys and records at once; encrypted bytes still held by providers until the old deal ends (at most about 30 days) can no longer be decrypted. This is called crypto-shredding.

5. Sharing keys

Each account has a public key. Sharing a folder locks the folder's key to the recipient's public key and signs the share; the server only carries the sealed package. Public keys are handed out by the gateway for now, so the app shows a fingerprint to compare with the person, remembers it and warns if it changes. Publishing public keys on the TOG network itself, so not even the gateway could swap them, is planned. Ending a share cuts access at the server at once; what the person already read stays with them.

6. Public links

A link looks like https://server/l/id#key. Browsers and apps never send the part after # to the server, so the server knows the link exists, how often it was opened and when it expires, but cannot open it. With a password, the key comes from the link and the password together. Whoever has the link has the key, so the operator can open a public link that is reported for abuse; private files without a link cannot be opened by anyone but you and the people you share with.

7. If something disappears

  • A storage provider disappears: files are rebuilt from the remaining pieces, and renewals pick providers that work.
  • The gateway is down: nothing can be uploaded or downloaded until it is back; files in your sync folder stay on your computer.
  • You lose a device: revoke it from another device.
  • You lose your password and phrase: without a signed-in device, files cannot be recovered. That is the price of nobody else having your keys.

8. Alpha status

TOG Drive is an alpha on The Only Grid test network, which may be restarted from scratch, erasing data. The encryption format is not frozen yet, and an independent audit of the client cryptography is planned before a public launch with real data. Redundancy on the small test network is lower than it will be on the main network. Some features described here (public keys on the network, opening links in a browser, mobile apps) are not finished. Use it for trying things out and keep copies of important files elsewhere.
